# CT-131 — Swagger UI público, operações só com Authorize

- **Data:** 2026-10-05 (~16:07–16:20)
- **Executor:** usuário (responsável pelo projeto)
- **Commit:** sem commit (pasta sem git)
- **Ambiente:** Windows 10, Docker Desktop (contêiner `rag-postgres`, `pgvector/pgvector:pg17`), aplicação local em `http://localhost:8080`, navegador com Swagger UI
- **Card / requisito:** HU-009 / RF-009 (CA-01, FA-01); ADR-013 — prioridade P2

## Passos executados

Clientes: **Cliente A = id 6** e **Cliente B = id 7** (o roteiro usa 1 e 2; trocar os ids é permitido).

1. Abrir `http://localhost:8080/swagger-ui/index.html` e `http://localhost:8080/v3/api-docs` sem chave.
2. Sem **Authorize**, `GET /clients/{clientId}` (passo do roteiro).
3. Abrir **Authorize** e conferir o esquema.
4. **Authorize** com a chave do Cliente A; `GET /clients/6` e `GET /clients/7`.
5. **Logout** e chamar `GET /clients/6` sem `X-API-Key`.

## Resultado esperado

1. As duas páginas abrem sem chave; o Swagger lista **Clientes**, **Documentos**, **Busca** e **Resposta**; o `/v3/api-docs` tem `securitySchemes.apiKey` com `"in": "header"` e `"name": "X-API-Key"`.
2. `401`.
3. Esquema `apiKey (apiKey)`, cabeçalho `X-API-Key`.
4. `200` para o próprio cliente e `403` para o outro.
5. `401`.

## Resultado obtido

```text
1. Swagger UI aberto: grupos Clientes, Busca, Documentos, Resposta e botão Authorize
   /v3/api-docs (JSON): ... "securitySchemes":{"apiKey":{"type":"apiKey","name":"X-API-Key","in":"header"}}

2. GET /clients/1 sem Authorize
   401  title "Não autenticado", detail "Informe uma chave de API válida no cabeçalho X-API-Key."
        content-type: application/problem+json

3. Available authorizations: apiKey (apiKey) — Name: X-API-Key, In: header

4. chave do Cliente A
   GET /clients/6  →  200 {"id": 6, "name": "Cliente A", "createdAt": "2026-10-05T13:43:13.378806Z"}
   GET /clients/7  →  403 "Acesso negado"

5. depois do Logout, GET /clients/6 sem X-API-Key  →  401 "Não autenticado"
```

## Observações

- O roteiro pede uma janela anônima no passo 1. O print não prova isso, mas as páginas abriram e a chamada do passo 2, feita sem chave, deu 401, que é o que o passo quer mostrar.
- No passo 5, a chamada sem chave foi feita com `curl` sem `X-API-Key`, depois do Logout no Swagger. O efeito conferido é o mesmo: sem chave, 401.
- O automático CT-085 (`SecurityConfigTest`: documentação pública, operações protegidas, `securitySchemes` no `/v3/api-docs`) cobre o mesmo comportamento e está OK.
