- **Data:** 2026-10-05
- **Executor:** usuário (responsável pelo projeto)
- **Commit:** sem commit (pasta sem git)
- **Ambiente:** Windows 10, Docker Desktop (contêiner `rag-postgres`, `pgvector/pgvector:pg17`), aplicação local em `http://localhost:8080` com `OPENAI_API_KEY` real, Swagger UI e `psql`
- **Card / requisito:** HU-006 / RF-006 (CA-01, CA-02, RN-01, RN-04) — prioridade **P1**

## Passos executados

O usuário cadastrou clientes novos para os testes do HU-006: **Cliente A = id 6** e **Cliente B = id 7** (o roteiro usa 1 e 2; trocar os ids é permitido).

1. Swagger UI → **Authorize** com a chave do Cliente A (id 6).
2. `POST /clients/6/documents?documentType=CONTRACT` com `contrato.pdf`.
3. O mesmo com `sinistro.pdf` (`CLAIM`) e `vistoria.pdf` (`INSPECTION`).
4. `SELECT` do roteiro com `WHERE d.client_id = 6`.

## Resultado esperado

Cada envio responde `201`, com `location: /clients/6/documents/{id}` e corpo com `id`, `clientId` `6`, `fileName` sem pasta, `documentType` enviado, `createdAt` e `totalChunks` maior que 0. No banco, 3 documentos do cliente 6; para cada um, `chunks` = `totalChunks` e `chunk_client_min` = `chunk_client_max` = `6`.

## Observações

- A coluna `chunk_client_max` fica cortada no print; o `max = 6` foi conferido via `psql` em 2026-10-05. Nessa conferência o contrato já é o id 9, porque o CT-126 reenviou o arquivo; o id 6 ficou sem chunks.
- O cabeçalho `location` não aparece: os prints cortam antes de **Response headers**. O teste automático CT-052 (`DocumentControllerTest`, `Location: /clients/{id}/documents/{id}`) confere esse cabeçalho e está OK.
- Em cada documento, `chunks` é igual a `totalChunks` (2, 1 e 2).
